On Phone, put a select in a `Field row` of a `FieldGroup`, as the [Settings Forms](/components/settings-forms) do: the value and its up-down chevrons sit at the row's end, like an iOS pop-up button, and the menu opens from the row's end, sized to its options. The row sets its height, insets and type, so the Phone previews show rows without the `variant` and `size` controls.

### Column configuration

<ComponentPreview details={<>
  <p>A column-visibility panel built with <code>Popover</code> and <code>Switch</code>. Toggling a switch moves the column between shown and hidden groups.</p>
  <p>On a phone the panel is a sheet (<code>Dialog</code> with <code>mobileVariant="sheet"</code>) of <code>Field</code> rows with switches, in a fixed order: as in iOS settings, a row stays in place when its switch changes.</p>
</>} code={`const allColumns = [
  { id: "name", label: "Name" },
  { id: "email", label: "Email" },
  { id: "role", label: "Role" },
  { id: "status", label: "Status" },
  { id: "created", label: "Created at" },
  { id: "lastLogin", label: "Last login" },
  { id: "avatar", label: "Avatar" },
  { id: "phone", label: "Phone" },
]
const [shown, setShown] = useState(["name", "email", "role", "status"])
const heading = useRef<HTMLDivElement>(null)
const toggle = (id: string) => {
  setShown((prev) =>
    prev.includes(id) ? prev.filter((c) => c !== id) : [...prev, id]
  )
}
const shownColumns = allColumns.filter((c) => shown.includes(c.id))
const hiddenColumns = allColumns.filter((c) => !shown.includes(c.id))

// Desktop: a popover; a switch moves its column between the shown and hidden lists
<Popover>
  <Popover.Trigger>
    <Button color="secondary" variant="outline" size="sm">
      <SettingsSlider width={15} height={15} /> Columns
    </Button>
  </Popover.Trigger>
  <Popover.Content minWidth={240} side="bottom" align="start">
    <div className="py-1.5">
      {shownColumns.map((col) => (
        <div
          key={col.id}
          className="flex items-center justify-between gap-4 px-3 py-1.5 cursor-pointer hover:bg-alpha/5"
          onClick={() => toggle(col.id)}
        >
          <span className="text-sm">{col.label}</span>
          <Switch checked aria-label={col.label} />
        </div>
      ))}
      {hiddenColumns.map((col) => (
        <div
          key={col.id}
          className="flex items-center justify-between gap-4 px-3 py-1.5 cursor-pointer hover:bg-alpha/5"
          onClick={() => toggle(col.id)}
        >
          <span className="text-sm text-tertiary">{col.label}</span>
          <Switch checked={false} aria-label={col.label} />
        </div>
      ))}
    </div>
  </Popover.Content>
</Popover>

// Phone: a sheet of switch rows in a fixed order
<Dialog>
  <Dialog.Trigger>
    <Button color="secondary" variant="outline" size="sm">
      <SettingsSlider width={15} height={15} /> Columns
    </Button>
  </Dialog.Trigger>
  <Dialog.Content mobileVariant="sheet" onOpenAutoFocus={(event) => { event.preventDefault(); heading.current?.focus({ preventScroll: true }); }}>
    <Dialog.Header>
      <div ref={heading} tabIndex={-1} className="outline-none"><Dialog.Title>Columns</Dialog.Title></div>
    </Dialog.Header>
    <Dialog.Body>
      <FieldGroup>
        {allColumns.map((col) => (
          <Field row key={col.id} label={col.label}>
            <Switch color="accent" checked={shown.includes(col.id)} onCheckedChange={() => toggle(col.id)} />
          </Field>
        ))}
      </FieldGroup>
    </Dialog.Body>
  </Dialog.Content>
</Dialog>`} previewMinHeight={168}>

## API

Use `aria-labelledby` with the ID of a visible field label. The default trigger includes that label and its current value or placeholder in its accessible name. `aria-label`, `aria-describedby` and `aria-invalid` also reach the default trigger. Custom triggers manage their own accessibility attributes.

The open list is a `listbox` (`aria-multiselectable` with `multiple`) named by `aria-labelledby`, then `aria-label`, then the default trigger; with a custom `trigger`, pass one of the two so the list has a name. `aria-selected` follows the selection and `aria-activedescendant` the highlighted option. Each option group is a `group` named by its label, so screen readers announce the group, and the arrow keys move through the options of every group in order. Typing a letter moves to the next matching option; Ctrl, Cmd and Alt shortcuts are left alone. After an option is chosen or Escape is pressed, focus returns to the trigger, a custom one included.

Searchable menus name their input `Search options` by default. Set `searchAriaLabel` for a more specific search label without changing the trigger's accessible name or the visible placeholder.

## Styling

Phone options share Menu's 34px corners and 17/20px label scale with the optional `touch.css` stylesheet. Long labels wrap within their text column; selection indicators keep a separate slot. Custom option content must inherit the label line height and allow its text to shrink. Search stays fixed while the option list scrolls.

On phones, Select uses the visible Page or Dialog footer as the bottom limit for collision handling. Search keeps its height while the list scrolls within the available space. `avoidCollisions={false}` disables this adjustment.

Select reads these component tokens. Override them at any scope to restyle it:

- `--link-primary-text-color`: primary text color (default `light-dark(var(--blue-500), var(--blue-300))`)
- `--menu-font-size`: font size (default `var(--font-text-sm-size)`)
- `--menu-gutter`: gutter (default `spacing(1.5)`)
- `--menu-item-background-color`: item background color (default `light-dark(var(--alpha-08), var(--alpha-10))`)
- `--menu-item-gap`: item gap (default `spacing(1.5)`)
- `--menu-item-padding`: item padding (default `spacing(1.5) spacing(2)`)
- `--menu-line-height`: line height (default `var(--font-text-sm-line-height)`)
- `--menu-radius`: radius (default `var(--radius-xl)`)
- `--menu-separator-background-color`: separator background color (default `var(--color-border)`)
