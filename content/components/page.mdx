## Phone

A page needs a bounded parent. These demos use a 420px frame on desktop and the full viewport on phones, without an outer border or rounded container:

```css
.page-frame {
  height: 420px;
  overflow: hidden;
  border: 1px solid var(--color-border);
  border-radius: var(--radius-xl);
}

@media (max-width: 767px) {
  .page-frame {
    height: 100dvh;
    border: 0;
    border-radius: 0;
  }
}
```

Under 768px the header contains a 44px toolbar row with 10px below it, plus the device top safe area. It floats: at rest nothing shows, and content scrolled under it turns it to glass with a hairline. The content keeps its place through `--page-top`, the top inset and the bar together, also for anything else that has to start below the bar, such as a banner.

Keep the row to a title and one group of actions. The bar has no room for a second row, so anything set under `Page.Bar`, such as a search field, belongs at the top of `Page.Content` on a phone. `useBreakpoint("md")` tells which one to render. Use `Page.Leading` for a Back button or the menu button of a sidebar. The title stays centred between the leading and trailing controls.

For a phone bar of its own, with a large title, a search field, a button group or a bottom bar, put a [Toolbar](/components/toolbar) in the page. Under 768px it replaces `Page.Header` and `Page.Footer`, which stay the desktop header and footer.

Use it inside `SidebarInset` for a whole app, see the [app sidebar](/components/sidebar#app).

## API

### Page

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `width` | `"full" \| "wide" \| "column"` | `"full"` | Column that header and content share: edge to edge, 1280px or 768px, centred |
| `surface` | `"plain" \| "grouped"` | `"plain"` | Mobile canvas and field-group palette; desktop colors stay unchanged |
| `className` | `string` | — | Applied to the root element |

All other `<div>` attributes are forwarded to the root.

### Page.Header

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `background` | `"glass" \| "solid"` | `"glass"` | Mobile toolbar background |
| `divider` | `boolean` | `true` | Shows a divider once the content has scrolled under the header |
| `className` | `string` | — | Applied to the band |

Children stand in the shared column. All other `<div>` attributes are forwarded to the band.

### Page.Content

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `fill` | `boolean` | `false` | The content fills the page and scrolls inside itself, from 768px up |
| `onScroll` | `UIEventHandler` | — | Called on every scroll, after the page has read the position |
| `className` | `string` | — | Applied to the element that scrolls |

Children stand in the shared column. All other `<div>` attributes and `ref` go to the element that scrolls.

### Page.Footer

Actions stay below the scrolling `Page.Content`. The footer shares the page column and includes at least 16px of bottom padding, or the device's bottom safe area when larger. Give `Page` a bounded height, such as `100dvh`, to keep the footer at the bottom of the screen. Native div attributes are forwarded to the footer.

### Compound parts

| Part | Element | Purpose |
|------|---------|---------|
| `Page.Leading` | `<div>` | Back or menu controls on the leading side of the bar |
| `Page.Bar` | `<div>` | Row of the title and the actions |
| `Page.Heading` | `<div>` | Title with what stands beside it |
| `Page.Title` | `<h1>` | Page heading |
| `Page.Subtitle` | `<div>` | Status of the page, including badges and text |
| `Page.Actions` | `<div>` | Buttons on the trailing side of the bar |

## Styling

`surface="plain"` is the default mobile canvas. Use `surface="grouped"` for screens of related field groups: light mode uses a gray canvas with white groups; dark mode uses the corresponding base surface levels. This palette is separate from the bars' `background="glass" | "solid"` material and leaves desktop colors unchanged.

`Page.Header` and `Page.Footer` accept `background="glass"` (the default) or `background="solid"`. Use solid bars when the content should not show through them on phones.

Page reads these component tokens. Override them at any scope to restyle it:

- `--safe-area-inset-top`: shared top inset for Page and Dialog (defaults to `env(safe-area-inset-top, 0px)`); override it for an embedded screen with its own status bar
- `--page-background`: canvas color; mobile follows `surface`, desktop defaults to `var(--color-surface)`
- `--page-bar-gap`: gap between title and actions (default `24px`)
- `--page-bar-height`: bar height (default `36px`)
- `--page-bar-height-phone`: bar height on a phone (default `44px`)
- `--page-bar-line`: hairline of the glass bar (default `light-dark(rgb(0 0 0 / 10%), var(--color-border))`)
- `--page-bar-veil`: translucent bar fill derived from the current mobile canvas
- `--page-content-padding-bottom`: bottom of the content (default `48px`)
- `--page-content-padding-top`: top of the content on a phone (default `16px`)
- `--page-gutter`: side gutter on a phone (default `16px`)
- `--page-gutter-wide`: side gutter and top of the content from 768px up (default `24px`)
- `--page-header-padding-bottom`: gap between the bar and the line (default `12px`)
- `--page-header-padding-top`: top of the header (default `12px`)
- `--page-title-font-size`: title font size (default `20px`)
- `--page-title-line-height`: title line height (default `26px`)
- `--page-width`: width of the column, any value
- `--page-width-column`: `column` width (default `768px`)
- `--page-width-wide`: `wide` width (default `1280px`)

### Footer spacing

`Page.Footer` stays below the scrolling content. Set `--page-footer-gutter` when its primary action needs a larger horizontal inset than the fields. `--page-footer-padding-bottom` controls the space below it, including the safe area.

```css
.mobile-form {
  --page-footer-gutter: 24px;
  --page-footer-padding-bottom: max(24px, env(safe-area-inset-bottom, 0px));
}
```
