On Phone, put an input in a row of a `FieldGroup`, as the [Forms: Settings](/components/settings-forms) do. The row is its frame and sets its height, insets and type, so the Phone previews show rows without the `size`, `gutterSize`, `pill` and `variant` controls.

### Overview

<ComponentPreview className={phoneRowsStyles.PhoneRowsPreview} details={<>
  <p>Use <code>variant</code> to stylize the input. <code>ghost</code> has no border and no fill, for a field its container already frames, such as the search line at the top of a dialog; it still turns red when <code>invalid</code>. <code>size</code> sets the control <code>height</code> and gives a <code>gutterSize</code> (the horizontal padding) and a <code>font-size</code>, each of which can be overridden; Input shares the 9-step size scale with Button, Select, SelectControl and SegmentedControl, so adjacent controls of one <code>size</code> line up. <code>pill</code> rounds it fully.</p>
  <p><code>startAdornment</code> puts content before the value, such as a prefix or a search icon, and <code>endAdornment</code> after it, such as a character counter. <code>gutterSize</code> sets the space at the edges (a negative margin on the adornment, such as <code>-ml-2</code>, fine-tunes it), and <code>gap</code> on the container the space between the adornment and the value. <code>onClear</code> shows a built-in clear button while the input has a value and is not disabled or read-only; clicking it keeps focus in the input. <code>opticallyAlign</code> (<code>"start"</code> or <code>"end"</code>) offsets the gutter so the text lines up with the content around it, here the label; on a <code>Field</code> it is forwarded to its control.</p>

A start adornment is a prefix of the value and trailing <code>text-secondary</code> text takes the row's accessory color; the clear button is the filled circle of an iOS text field, shown only while the value is being edited, and a long value stops 6px before it. An error is the row's <code>errorMessage</code> under it. Browser autofill extensions are a desktop matter: on iOS autofill comes from the system above the keyboard. An Input in a <a href="/components/toolbar#overview">Toolbar</a> takes the bar's search field, and one with <code>type="search"</code> at the top of the content is <a href="/components/toolbar#search-in-the-content">the same glass field</a> under a large title.</p>

Plex UI also provides a `FieldError` component (`@plexui/ui/components/FieldError`) that pairs well with invalid inputs. It renders an error icon with a message styled for form validation; a long message wraps under its first line, and `icon={false}` leaves the icon out where the message stands alone, such as under a centered code input.

## Styling

Input reads these component tokens. Override them at any scope to restyle it:

- `--input-border-color-invalid`: border color invalid (default `var(--color-border-danger-outline)`)
- `--input-gap-lg`: gap lg (default `10px`)
- `--input-gap-md`: gap md (default `8px`)
- `--input-gap-sm`: gap sm (default `6px`)
- `--input-gap-xs`: gap xs (default `4px`)
- `--input-outline-border-color`: outline border color (default `var(--color-border-primary-outline)`)
- `--input-outline-border-color-focus`: outline border color focus (default `var(--alpha-50)`)
- `--input-outline-border-color-hover`: outline border color hover (default `light-dark(var(--alpha-25), var(--alpha-30))`)
- `--input-placeholder-text-color`: placeholder text color (default `var(--color-text-tertiary)`)
- `--input-soft-background-color`: soft background color (default `var(--color-background-primary-soft-alpha)`)
- `--input-soft-border-color-focus`: soft border color focus (default `var(--alpha-20)`)
- `--input-text-color`: text color (default `var(--color-text)`)
