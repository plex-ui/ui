### Overview

<ComponentPreview className={phoneRowsStyles.PhoneRowsPreview} details={<>Use <code>placeholder</code> for empty content; <code>content</code> starts the editor with markdown of every format it offers: <strong>bold</strong>, <em>italic</em>, links, ordered and unordered lists. Click inside formatted text to see its toolbar buttons toggle. <code>variant</code> switches between <code>outline</code> (default) and <code>soft</code>.<br /><br /><code>formats</code> chooses what the editor offers: <code>bold</code>, <code>italic</code>, <code>orderedList</code>, <code>bulletList</code> and <code>link</code>, all five by default. A format left out has no toolbar button, keyboard shortcut or input rule. In pasted text its markers stay text, as if they were typed, and so do those of headings, quotes, code and rules, which the editor never offers. Pasted HTML and incoming markdown keep its text without it, and the markdown the editor writes leaves it out: with <code>bold, link</code> the italic and the lists of the formatted content become plain text. With <code>breaks</code>, a single newline is a line break, read and written as one newline. Both are read when the editor is created, so the example makes a new editor when they change.<br /><br /><code>field</code> wraps the editor in a <code>Field</code> with a label and a description: the editor receives <code>id</code>, <code>aria-describedby</code> and <code>aria-invalid</code> from it, and <code>invalid</code> shows the Field's linked error message. Without a Field, set an accessible name with <code>aria-label</code> and <code>invalid</code> on the editor itself. The invalid state is controlled by this example, not by a validator, and it and <code>disabled</code> keep the entered markdown. <code>toolbarEnd</code> renders custom content at the end of the toolbar, here an &ldquo;Edit translations&rdquo; button; <code>markdownEditorStyles.toolbarButton</code> gives it the style of the built-in toolbar buttons.<br /><br />On Phone the editor is a cell of a grouped form: put it in a <code>FieldGroup</code> whose <code>title</code> names it and whose <code>footer</code> describes it, at the cell's inset. The text takes the row's type and insets; the format buttons are 35px circles in a row under a hairline, as iOS draws a row of round buttons in a cell, and a format that is on is a solid circle. <code>variant</code> is a desktop setting: the cell has no outline. The link button works without a selection, adding the link at the caret; in a link it edits it, and the sheet's <em>Remove Link</em> row takes it off.</>} code={`import { MarkdownEditor, markdownEditorStyles } from "@plexui/ui/components/MarkdownEditor"
import { Field } from "@plexui/ui/components/Field"
import { FieldGroup } from "@plexui/ui/components/FieldGroup"
import { Translate } from "@plexui/ui/components/Icon"

function Example({ variant = "outline", formats, breaks = false, invalid = false, disabled = false, toolbarEnd = false }) {
  const [value, setValue] = useState("")

  return (
    <Field label="Description" description="Supports bold, italic, lists, and links."
      errorMessage={invalid ? "This field is required." : undefined}>
      <MarkdownEditor
        // formats and breaks are read when the editor is created: a new key makes a new one
        key={\`\${formats}-\${breaks}\`}
        aria-label="Description"
        placeholder="Enter text..."
        value={value}
        onChange={setValue}
        variant={variant}
        formats={formats} // e.g. ["bold", "link"]
        breaks={breaks}
        disabled={disabled}
        toolbarEnd={toolbarEnd && (
          <button type="button" disabled={disabled} className={markdownEditorStyles.toolbarButton}
            aria-label="Edit translations" title="Edit translations">
            <Translate />
          </button>
        )}
      />
    </Field>
  )
}

// Phone: the editor is the cell of a FieldGroup; the label is the group's title, the description (or the error) its footer
<FieldGroup title="Description" footer={<span id="description-footer">Supports bold, italic, lists, and links.</span>}>
  <MarkdownEditor aria-label="Description" aria-describedby="description-footer" placeholder="Enter text..." value={value} onChange={setValue} />
</FieldGroup>`} previewMinHeight={300}>
  <MarkdownEditorOverviewDemo />
</ComponentPreview>

The editable element is a `textbox` with `aria-multiline`. A `<label for>`, including the label `Field` renders, cannot name a contenteditable region, so give the editor `aria-label`, or `aria-labelledby` pointing at a visible label. Toolbar buttons are toggles (`aria-pressed`) that follow the formatting at the caret, and a click in the text places the caret there. In the link dialog, Enter in a field saves the link, Enter on a button runs that button, Escape cancels, and Tab stays inside the dialog. `onChange` also fires once when the editor is created and whenever `disabled` changes.

## Styling

Markdown Editor reads these component tokens. Override them at any scope to restyle it:

- `--input-border-color-invalid`: border color invalid (default `var(--color-border-danger-outline)`)
- `--input-outline-border-color`: outline border color (default `var(--color-border-primary-outline)`)
- `--input-outline-border-color-focus`: outline border color focus (default `var(--alpha-50)`)
- `--input-outline-border-color-hover`: outline border color hover (default `light-dark(var(--alpha-25), var(--alpha-30))`)
- `--input-placeholder-text-color`: placeholder text color (default `var(--color-text-tertiary)`)
- `--input-soft-background-color`: soft background color (default `var(--color-background-primary-soft-alpha)`)
- `--input-soft-border-color-focus`: soft border color focus (default `var(--alpha-20)`)
- `--link-primary-text-color`: primary text color (default `light-dark(var(--blue-500), var(--blue-300))`)
