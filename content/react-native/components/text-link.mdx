### Overview

<ComponentPreview details={<>
  <p>A <code>TextLink</code> sits in running text: put it inside a <code>Text</code>, whose face, size and color it takes, with an underline, a subtle difference from the text around it. Change the paragraph's color (<code>colorClassName</code>) to see it. <code>primary</code> colors the link with <code>--link-primary-text-color</code> instead and drops the underline by default. <code>underline</code> turns the underline on or off; unset, it is on unless the link is <code>primary</code>. <code>weight</code> sets the link's weight (the web's font-weight class); by default it takes the text's own.</p>
  <p>A tap opens <code>href</code> with React Native's <code>Linking</code>: a link of the app (its own scheme or a universal link) or a site in the browser; on the web it is an anchor, and an <code>http://</code> or <code>https://</code> URL opens in a new tab. An icon such as <code>ArrowTopRightSm</code> can mark an external link. <code>onPress</code> runs first, and <code>event.preventDefault()</code> keeps the link from opening, for a link your router handles. iOS highlights a pressed link as its text views do; Android draws the press layer of the Plex Android look behind the text.</p>

With `href` the link is a `link` for screen readers; with only `onPress` it is a `button`. The web's `to`, `as` and `target` are for a web router and a browser's tabs: in React Native a router's own link handles `onPress` (`weight` and `style` stand for the font-weight class and `className`), and `PlexUIProvider`'s `linkComponent` has no counterpart.
