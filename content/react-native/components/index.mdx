Every example on these pages is live, drawn by react-native-web. The switch above the examples draws them as iOS or Android, light or dark.

## Setup

<UsageBlock>{`npm install @plexui/react-native react-native-svg react-native-safe-area-context
# optional: native glass on iOS 26, a blur elsewhere
npx expo install expo-glass-effect expo-blur`}</UsageBlock>

Wrap the app in `ThemeProvider` inside `SafeAreaProvider`, and put one `Toaster` in it for `toast()`:

```tsx
import { ThemeProvider, Toaster, interFonts } from "@plexui/react-native"
import { SafeAreaProvider } from "react-native-safe-area-context"

export default function App() {
  return (
    <SafeAreaProvider>
      <ThemeProvider fonts={interFonts}>
        <Screens />
        <Toaster />
      </ThemeProvider>
    </SafeAreaProvider>
  )
}
```

`ThemeProvider` follows the device: iOS draws the iOS 26 look, Android the Plex Android look, and Android 16's Material 3 Expressive where it has no pattern of its own; the web the iOS look. `platform` overrides it, `scheme` takes `"light"`, `"dark"` or `"system"`, and `brand` sets a product's colors, faces and radii over the Plex UI defaults. `selectionColor` is the on color of every Switch, Checkbox and RadioGroup that sets none of its own, and a nested `ThemeProvider` takes its parent's: `"primary"` (the default) is the Plex primary, the ink, as on the web; `"accent"` is each platform's own, on iOS a green switch and accent checkboxes and checkmarks, the iOS tint, and on Android the accent for all of them.

`fonts` sets the kit's faces; without it each platform draws its own system face. It takes one set of faces for every platform, or a set per drawn platform, `{ ios, android }`, of which a provider takes the one of its `platform` (a platform left out draws its system face). `interFonts` and `robotoFonts` are the family names that `@expo-google-fonts/inter` and `@expo-google-fonts/roboto` register. An Android device has Roboto as its system face already, but the web needs it loaded for the Android look: in a browser on a Mac the Material look would otherwise draw in the browser's system face, not Roboto.

```tsx
import { ThemeProvider, interFonts, robotoFonts } from "@plexui/react-native"
import { Inter_400Regular, Inter_500Medium, Inter_600SemiBold, Inter_700Bold } from "@expo-google-fonts/inter"
import { Roboto_400Regular, Roboto_500Medium, Roboto_600SemiBold, Roboto_700Bold } from "@expo-google-fonts/roboto"
import { useFonts } from "expo-font"

export default function App() {
  const [loaded] = useFonts({
    Inter_400Regular, Inter_500Medium, Inter_600SemiBold, Inter_700Bold,
    Roboto_400Regular, Roboto_500Medium, Roboto_600SemiBold, Roboto_700Bold,
  })
  if (!loaded) return null
  return (
    <ThemeProvider fonts={{ ios: interFonts, android: robotoFonts }}>
      <Screens />
    </ThemeProvider>
  )
}
```

`viewportWidth` is the width the phone layer is laid out for, in place of the window's: a phone drawn in a frame inside a wider window, such as a gallery or a review page, sets the frame's width (402 for an iPhone 17 Pro). A nested `ThemeProvider` takes its parent's.

Names that clash between the platforms:

- **Navigation bar** is the top bar on iOS (Toolbar) and the bottom bar of destinations on Android (Tab Bar).
- **Toolbar** is the bottom bar of actions on iOS, floating in glass; Material's floating toolbar is not used on Android, where the bottom of a screen holds one wide action or a field.
- **Tabs** on Android sit under a top app bar and switch views inside one screen; use Segmented Control for that.
