At 767px and below, `mobile-variant="alert"` presents a compact centered glass alert, a confirmation or a request for one short value, with inline actions and no close icon. Use `mobile-variant="sheet"` for forms and details: it opens at the bottom with a grabber, a leading Close button and a centered title. Both variants preserve the desktop appearance.

Alert actions wrap onto separate rows when their labels need more space. Set `<DialogFooter mobile-layout="stacked">` when the actions should always stack. Put long sheet content in `DialogBody` to keep the header and actions visible while the body scrolls.

### Segmented composer header

A Close action, an Event/Reminder segmented control, and a Save action share the sheet header. Switching the segment changes the fields while preserving each draft. The fields follow the native composer: the title and the notes are named by their placeholders, each in its own group; an event shows its day and hours in one row that opens the calendar; a reminder lists Date, Time and Urgent with an icon each, a set value under its title in the accent, and a switch for the time. ### Setup choices

Rows that each open the next step: a leading icon, a title, an optional subtitle and a disclosure chevron, and the whole row is one button. On phones the sheet is on the plain surface, with the rows in one group or each in its own rounded cell. A row replaces the choices with its step in the same sheet; Back returns to the row that opened it and Close dismisses the sheet. Desktop uses a centered dialog with Back in its footer. Add confirms the local sample; nothing is sent.

Copy the [SetupChoicesSheet helper](https://github.com/plex-ui/ui/blob/master/components/docs/vue/SetupChoicesSheet.ts), [method data](https://github.com/plex-ui/ui/blob/master/components/docs/setupChoicesData.ts), and [shared styles](https://github.com/plex-ui/ui/blob/master/components/docs/SetupChoicesSheet.module.css) together, preserving their relative paths. The helper uses Dialog, Toolbar, NavigationButton, FieldGroup and Button, with line icons from `lucide-static` and `@hugeicons/core-free-icons` (the hero) whose weight the sheet sets: a native setup sheet draws its large glyphs with a light line. `layout` and `subtitles` choose the presentation; the `add` event receives the confirmed method.

Over a phone keyboard the dialog covers the part of the window the keyboard leaves visible, so a sheet sits on the keyboard and a centered panel stays in view. Inside a [PhoneLayout](/vue/components/phone-layout) it portals into the PhoneLayout box and covers it instead of the window.

**DialogTrigger**: opens the dialog; renders its child element (Reka's `as-child`).

**DialogHeader**: wrapper for title, description and an optional header action. In a phone Sheet the header is the Sheet's Toolbar: Close at the leading edge, the title centered on the 44px row of controls and the header action at the trailing edge, as in the iOS 27 kit. A description the reader sees is the title's second line; a visually hidden one only names the sheet. If the Dialog has its own top Toolbar, that one replaces the header's bar. In a phone Sheet, `background` sets how the bar meets the body scrolled under it: `glass` (the default), `soft`, `hard` or `solid`, as on a [Toolbar](/vue/components/toolbar#background).

**DialogHeaderAction**: positions one toolbar control beside Close on desktop and opposite Close in a mobile sheet. Place it directly inside DialogHeader (a fragment there is fine, a component of your own that returns it is not: a phone Sheet looks for it among the header's own parts to stand it at the trailing edge) and label icon-only controls. Mobile alerts hide this slot.

**DialogTitle**: accessible heading for the dialog.

**DialogDescription**: supporting text under the title.

**DialogBody**: the scrolling part between the header and the footer. With it, only the body scrolls. Accepts `class`.

**DialogFooter**: footer area for action buttons. Mobile alert actions are 48px pills in a wrapping row by default. Mobile sheets use 50px pill actions, 24px side gutters and at least 24px below the actions, including the bottom safe area. Standard dialogs and sheets stack their mobile actions.

## Styling

Use `surface="grouped"` on dialog content for grouped forms. The default `surface="plain"` suits confirmations and standalone content. Mobile dialogs use elevated dark surface levels; the choice is independent of alert/sheet geometry and the bars' `background`.

Dialog reads the shared semantic color, typography and spacing tokens listed in [Design tokens](/docs/foundations/design-tokens), so it follows theme changes made there. Override these Dialog tokens at any scope:

- `--dialog-panel-background`: panel color, and the color of a Sheet's soft, hard and solid bars; mobile follows the selected elevated surface role
- `--dialog-close-background`: close button background (default `transparent`)
- `--dialog-close-background-hover`: close button background on hover
- `--dialog-z-index`: stack order of the overlay and the dialog (default `50`; `z-index` sets it)
- `--dialog-viewport-height`: the height the panel fits in (default `100dvh`; the dialog sets it over a phone keyboard and inside a PhoneLayout)
- `--dialog-steps-background`: background of a step, which covers the one under it as it comes in (default the panel color)

Standard mobile appearance uses these tokens:

- `--dialog-mobile-close-size`: visible close-button circle (default `--control-size-md`, 32px)
- `--dialog-mobile-close-icon-size`: close SVG box (default `--control-icon-size-2xl`, 24px; the glyph occupies about 12px)
- `--dialog-mobile-close-background`: mobile close button fill (default secondary soft)
- `--dialog-mobile-radius`: mobile panel corner radius (default `--radius-4xl`, 24px)
- `--dialog-mobile-action-size`: mobile footer height and close-button touch target (default `--control-size-2xl`, 44px)
- `--dialog-mobile-action-radius`: mobile footer button radius (default `--radius-full`)
- `--dialog-mobile-action-font-size`: mobile footer button text size (default `--control-font-size-lg`)

Alert and Sheet use these additional tokens:

- `--dialog-alert-width`: compact alert width (default `300px`, `320px` from a 414px wide phone with `touch.css`, as a native alert at 430pt; capped by the viewport)
- `--dialog-alert-radius`: alert corner radius (default `34px`)
- `--dialog-alert-padding`: alert outer padding, the inset of a field and the actions (default `14px`)
- `--dialog-alert-action-height`: minimum Alert action height (default `48px`)
- `--dialog-alert-field-height`: height of a field in the alert on a phone (default `52px`)
- `--dialog-alert-background`, `--dialog-alert-backdrop-filter`: alert material on a phone (with `touch.css` the mobile glass, `--mobile-glass-background`, over `blur(10px)`)
- `--dialog-alert-message-color`, `--dialog-alert-message-size`, `--dialog-alert-message-leading`: alert message on a phone (default `var(--color-text)`, `17px`, `22px`)
- `--dialog-alert-fill`: fill of a soft Cancel and a soft field in the alert (with `touch.css` `--alpha-12`)
- `--dialog-alert-action-gap`, `--dialog-alert-action-font-weight`: gap between two inline actions and their weight (default `8px`, `600`)
- `--dialog-sheet-action-height`: minimum Sheet action height (default `50px`)
- `--dialog-sheet-radius`: sheet top corner radius (default `38px`; fullscreen stays square)
- `--dialog-mobile-scrim`: dim behind a phone Sheet or Alert (default black at 20% in light and 50% in dark, as native iOS 26); desktop keeps `rgb(0 0 0 / 0.5)`
- `--dialog-sheet-close-size`: sheet close-button circle and touch target (default `--control-size-2xl`, 44px)
- `--dialog-sheet-close-icon-size`: sheet close SVG box (default `34px`; the visible cross is about 17px)
- `--dialog-mobile-type-size`: Alert and Sheet heading, description and actions (default `17px`)
- `--dialog-mobile-type-leading`: Alert and Sheet heading, description and action line height (default `22px`)
