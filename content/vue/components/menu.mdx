## API

**Note:** Menu prevents `Tab` from advancing focus. For generic popover content use [Popover](/vue/components/popover) instead.

**Menu** (root)

<PropsTable data={[
  { prop: "force-open", type: "boolean", description: "Keep menu open (controlled)" },
  { prop: "modal", type: "boolean", default: "false", description: "Whether menu is modal (focus trap)" },
  { prop: "@open", type: "() => void", description: "Emitted when menu opens" },
  { prop: "@close", type: "() => void", description: "Emitted when menu closes" },
]} />

**MenuTrigger**: renders its child (e.g. a Button) as the element that toggles the menu. Other attributes and listeners reach the child.

<PropsTable data={[
  { prop: "disabled", type: "boolean", default: "false", description: "Prevent the menu from opening" },
]} />

**MenuContent**

<PropsTable data={[
  { prop: "width", type: 'number | "auto"', default: "fits content, 250 on a phone", description: 'Panel width (numbers are pixels). Without it the panel fits its content, or with touch.css on a phone is 250px, as an iOS menu; "auto" fits the content there too' },
  { prop: "min-width", type: 'number | "auto"', default: "300", description: "Minimum panel width" },
  { prop: "max-height", type: "number", description: "Maximum panel height, in pixels" },
  { prop: "pill", type: "boolean", default: "false", description: "Rounder list with fully rounded rows, for menus beside pill controls. MenuSubContent takes it too" },
  { prop: "side", type: '"top" | "right" | "bottom" | "left"', default: '"bottom"', description: "Preferred placement. Without it, and without side-offset, a menu on a phone opens upward from a trigger in the lower half of the screen" },
  { prop: "side-offset", type: "number", default: "5", description: "Distance from the trigger, in pixels. Without it a menu on a phone covers its trigger" },
  { prop: "align", type: '"start" | "center" | "end"', default: '"center"', description: "Alignment relative to trigger" },
  { prop: "align-offset", type: "number", default: "-5", description: "Offset from the start or end alignment, in pixels. 0 with center alignment, and on a phone when the menu covers its trigger" },
  { prop: "layout", type: '"vertical" | "horizontal"', default: '"vertical"', description: "Layout direction. Use horizontal for icon toolbars" },
  { prop: "size", type: '"sm" | "md" | "lg"', default: '"md"', description: "Size of horizontal menu items (icon size + padding)" },
  { prop: "@close-auto-focus", type: "(event: Event) => void", description: "Emitted before focus returns to the trigger; call event.preventDefault() to keep it from moving there" },
  { prop: "@open-auto-focus", type: "(event: Event) => void", description: "Emitted before focus moves into the menu as it opens; call event.preventDefault() to leave focus where it is, as for a menu that stands open when its screen appears" },
]} />

**MenuItem**: list item. Listen to `@select` or `@click` for actions; without either the item is non-interactive content.

<PropsTable data={[
  { prop: "description", type: "string", description: "Second line under the label (or the description slot). The label turns semibold on its own" },
  { prop: "disabled", type: "boolean", default: "false", description: "Disable the item" },
  { prop: "danger", type: "boolean", default: "false", description: "Destructive action: the item is drawn in the danger color" },
  { prop: "@select", type: "(event: Event) => void", description: "Called when the item is selected; call event.preventDefault() to keep the menu open" },
  { prop: "@click", type: "(event: MouseEvent) => void", description: "Called when the item is clicked; also makes the item interactive" },
]} />

**MenuLink**: item that navigates. Internal paths render the link component from `PlexUIProvider` (for example vue-router's `RouterLink`); absolute `http(s)` URLs open in a new tab. Pass `href` or `to`, `disabled` (a disabled link does not navigate), `danger`, `as` and link attributes.

**MenuSeparator**: divider between items. No props.

**MenuGroup**: groups related items. Wraps `MenuItem`, `MenuLink`, or `MenuLabel`. No specific props.

**MenuLabel**: non-interactive label for a group. Accepts `class`.

**MenuHeader**: names what the menu acts on, above its items. The default slot is the title; the `media` slot is a picture before it (an image, an icon or an Avatar in a 32px square, 40px on a phone: an image or icon fills it, an image gets small rounded corners), and the `action` slot a MenuHeaderAction at the end.

<PropsTable data={[
  { prop: "description", type: "string", description: "Line under the title, such as the kind and size of a file (or the description slot)" },
]} />

**MenuHeaderAction**: round action at the end of a header, a menu item that closes the menu when selected. Its slot is the icon.

## Styling

With the optional `touch.css` stylesheet, phone menus use 34px corners (the iOS 27 kit Menu), 17px labels with 20px line height, and 13/18px subtitles. Rows are 42px, as in native iOS 26 menus, and long labels wrap and make a row taller. A pressed row is the capsule iOS draws under the finger: the whole row, 10px from the panel's edges, round at its ends, in one even gray (`--menu-press-background`). A submenu grows out of the row that opened it while the menu behind it steps back. A checked item keeps its checkmark without a persistent background, centered 28px from the panel's edge with labels at 43.5px, as native menus draw it; in a menu with checkmarks, plain rows and section titles start where the labels do. A menu and a submenu are 250px wide, as native iOS menus are, so a long label wraps under itself; an explicit width or minimum width still takes precedence, and a submenu of `auto` width fits its content.

On a phone, a menu taller than the room it has scrolls its items inside the panel, and they fade out over 32px at an edge they scroll past, as the soft scroll edge of the iOS 27 kit; in a browser without scroll-driven animations they scroll without the fade.

On a phone a menu without `side-offset` grows out of its trigger and covers it, as iOS menus do: its top is the trigger's top, or its bottom when it opens upward, and its aligned edge is the trigger's edge. Without `side` it opens toward the larger part of the screen, upward from a trigger in the lower half even when it would fit below. A desktop keeps the 5px gap below the trigger.

On phones, menus and submenus inside a Page or Dialog keep clear of its visible footer. Their available space updates when the footer or viewport changes.

A phone here is a window 767px wide or narrower, or the inside of a [PhoneLayout](/vue/components/phone-layout) or a [Dialog](/vue/components/dialog#api) with `layout="phone"`, at any window width. A menu opened in a PhoneLayout opens in its box and keeps inside it; one opened in a phone Dialog opens over the window, as on a phone.

A phone menu is glass over the page, as native iOS 27.2 menus are: white at 65% in the light theme and at 12% in the dark one, over an 18px blur of what is under it, which leaves the page's text unreadable through the panel (a 37 by 24pt switch knob behind a native menu spreads to 55 by 37pt). A thin edge draws the panel's outline on a white page, as native menus have. A trigger the panel covers whole, as a More button of a top bar, is hidden while the menu is open, as iOS turns a bar button into its menu; a wider trigger, as a form row, stays.

Menu reads these component tokens. Override them at any scope to restyle it:

- `--menu-checkbox-indicator-size`: checkbox indicator size (default `var(--font-text-lg-size)`)
- `--menu-font-size`: font size (default `var(--font-text-sm-size)`)
- `--menu-gutter`: gutter (default `spacing(1.5)`)
- `--menu-item-background-color`: item background color (default `light-dark(var(--alpha-08), var(--alpha-10))`)
- `--menu-mobile-background`: panel surface on a phone (default `light-dark(rgb(255 255 255 / 65%), var(--alpha-12))` glass)
- `--menu-mobile-backdrop-filter`: blur behind the panel on a phone (default `blur(18px)`)
- `--menu-default-width`: default width before a content-level override (none on desktop, 250px with touch styles)
- `--menu-default-min-width`: default minimum width before a content-level override (300px on desktop, 250px with touch styles)
- `--menu-horizontal-min-width`: minimum width of a horizontal menu (none on desktop, 250px with touch styles)
- `--menu-item-press-scale`: pressed surface scale (1 with touch styles; otherwise follows the pointer interaction scale)
- `--menu-item-gap`: item gap (default `spacing(1.5)`)
- `--menu-item-padding`: item padding (default `spacing(1.5) spacing(2)`)
- `--menu-line-height`: line height (default `var(--font-text-sm-line-height)`)
- `--menu-radio-indicator-hole-size`: radio indicator hole size (default `var(--font-text-3xs-size)`)
- `--menu-radio-indicator-size`: radio indicator size (default `var(--font-text-lg-size)`)
- `--menu-radius`: radius (default `var(--radius-xl)`; `34px` on a phone with `touch.css`, the iOS 27 kit Menu)
- `--menu-scroll-fade`: how far the items of a phone menu fade at an edge they scroll past (default `32px`)
- `--menu-separator-background-color`: separator background color (default `var(--color-border)`)
- `--menu-separator-gutter`: separator gutter (default `var(--menu-gutter) calc(-1 * var(--menu-gutter))`)
- `--radio-group-indicator-background-color`: indicator background color (default `var(--color-background-primary-solid)`)
- `--radio-group-indicator-border-color`: indicator border color (default `var(--color-border-primary-outline)`)
- `--radio-group-indicator-border-color-hover`: indicator border color hover (default `var(--alpha-25)`)
- `--radio-group-indicator-hole-background-color`: indicator hole background color (default `var(--color-text-primary-solid)`)
