### Select Control

A `SelectControl` is Select's button alone, for a list of your own: wrap it in a `MenuTrigger` or `PopoverTrigger` and give it the content. It takes Select's trigger styles, and on Phone it is the value of a row in a `FieldGroup`, with the value and its up-down chevrons at the row's end, like an iOS pop-up button. The same module exports `DropdownIcon` for custom menu triggers. Its `icon-type` accepts `"dropdown"` or `"chevronDown"`; the indicator keeps its proportions inside a Button.

<ComponentPreview className={phoneRowsStyles.PhoneRowsPreview} language="vue" details={<>Use <code>variant</code> to stylize the control: its styles are like those of <code>{"<Button>"}</code>, with the small differences of <code>{"<Input>"}</code>, and <code>ghost</code> has no frame. <code>size</code> sets the control's height, font size, gutter and the placement of its icon and indicator, on the 9-step scale of Button, Input, Select and SegmentedControl; <code>pill</code> rounds it fully and widens its gutter, and its clear action is a pill too. Pass a component to <code>StartIcon</code> to put an icon before the value, sized, spaced and colored by the control, and <code>dropdown-icon-type</code> picks the indicator. <code>selected</code> says the control holds a value and turns off the placeholder styling. It does nothing to the content, which is up to you, so here it follows the value: pick a period, or clear it. Listen to <code>@clear-click</code> (or pass <code>on-clear-click</code>) to make the control clearable: the clear action shows while it is <code>selected</code>. During <code>loading</code> the dropdown icon and clear action are hidden, the control is marked <code>aria-busy</code> and it ignores pointer and keyboard interaction; add <code>disabled</code> to dim it as well. <code>invalid</code> marks the control invalid; pair it with the field's <code>error-message</code>. <code>disabled</code> disables it both visually and accessibly. <code>block</code> stretches it across its container, here the 290px field. <code>optically-align</code> offsets the control by its gutter: <code>"start"</code> puts the start of a <code>ghost</code> control, its icon or its text, on the label's edge, and <code>"end"</code> puts the end of a block one, its indicator, on the field's end. A framed control keeps its gutter, so the example offers the setting for ghost only, and <code>"end"</code> only with <code>block</code>: a narrower control does not reach the field's end. The control's own <code>aria-labelledby</code> names it by the label and the value, as Select's trigger is named.<br /><br />On Phone the control is the value of a row in a <code>FieldGroup</code>: the value and its up-down chevrons sit at the row's end, as an iOS pop-up button. The row sets its height, insets, type and colors, so the Phone preview has no <code>variant</code>, <code>size</code>, <code>pill</code>, <code>StartIcon</code>, <code>dropdownIconType</code>, <code>block</code> and <code>opticallyAlign</code> controls. ## API

### Select

Use `aria-labelledby` with the ID of a visible field label. The default trigger includes that label and its current value or placeholder in its accessible name. `aria-label`, `aria-describedby` and `aria-invalid` also reach the default trigger. Custom triggers manage their own accessibility attributes.

The open list is a `listbox` (`aria-multiselectable` with `multiple`) named by `aria-labelledby`, then `aria-label`, then the default trigger; with a custom `trigger`, pass one of the two so the list has a name. `aria-selected` follows the selection and `aria-activedescendant` the highlighted option. Each option group is a `group` named by its label, so screen readers announce the group, and the arrow keys move through the options of every group in order. Typing a letter moves to the next matching option; Ctrl, Cmd and Alt shortcuts are left alone. After an option is chosen or Escape is pressed, focus returns to the trigger, a custom one included.

Searchable menus name their input `Search options` by default. Set `search-aria-label` for a more specific search label without changing the trigger's accessible name or the visible placeholder.

### SelectControl

Use `SelectControl` with any floating UI (e.g. `MenuTrigger`, `PopoverTrigger`). The control renders the trigger; you provide the dropdown content. The default slot is the control's content. Attributes and listeners that are not props land on the control's `<span role="button">`; `@keydown` receives only the keys the control does not handle itself. To decide when the control opens (or to keep it closed), listen to `@interact` and control the dropdown's `open` state yourself: the wrapping trigger then no longer opens on its own.

## Styling

Phone options share Menu's 34px corners and 17/20px label scale with the optional `touch.css` stylesheet. Long labels wrap within their text column; selection indicators keep a separate slot. Custom option content must inherit the label line height and allow its text to shrink. Search stays fixed while the option list scrolls.

On phones, Select uses the visible Page or Dialog footer as the bottom limit for collision handling. Search keeps its height while the list scrolls within the available space. `:avoid-collisions="false"` disables this adjustment.

Select reads these component tokens. Override them at any scope to restyle it:

- `--link-primary-text-color`: primary text color (default `light-dark(var(--blue-500), var(--blue-300))`)
- `--menu-font-size`: font size (default `var(--font-text-sm-size)`)
- `--menu-gutter`: gutter (default `spacing(1.5)`)
- `--menu-item-background-color`: item background color (default `light-dark(var(--alpha-08), var(--alpha-10))`)
- `--menu-item-gap`: item gap (default `spacing(1.5)`)
- `--menu-item-padding`: item padding (default `spacing(1.5) spacing(2)`)
- `--menu-line-height`: line height (default `var(--font-text-sm-line-height)`)
- `--menu-radius`: radius (default `var(--radius-xl)`)
- `--menu-separator-background-color`: separator background color (default `var(--color-border)`)

A standalone `SelectControl` reads these component tokens:

- `--input-border-color-invalid`: border color invalid (default `var(--color-border-danger-outline)`)
- `--input-outline-border-color`: outline border color (default `var(--color-border-primary-outline)`)
- `--input-outline-border-color-hover`: outline border color hover (default `light-dark(var(--alpha-25), var(--alpha-30))`)
- `--input-placeholder-text-color`: placeholder text color (default `var(--color-text-tertiary)`)
- `--input-text-color`: text color (default `var(--color-text)`)
- `--select-control-font-weight`: font weight (default `var(--font-weight-normal)`)
