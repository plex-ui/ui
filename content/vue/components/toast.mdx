<UsageBlock>{`import { Toaster, toast } from "@plexui/vue/components/Toast";`}</UsageBlock>

Render `<Toaster />` once near the root of your app, then call `toast(...)` from any handler. Toast is built on [vue-sonner](https://vue-sonner.vercel.app/), the Vue port of sonner. Its full API (`toast.promise`, `toast.loading`, `toast.dismiss`, `toast.custom`) is re-exported as-is. The examples call `toast` from the template; in an app, import it in `<script setup>`.

Remaining vue-sonner `Toaster` props (`expand`, `visible-toasts`, `hotkey`, `dir`, `swipe-directions`, etc.) are forwarded untouched. The `success-icon`, `error-icon`, `warning-icon`, `info-icon`, `loading-icon` and `close-icon` slots replace the default icons.

### toast

Re-exported from vue-sonner. The full surface (`toast()`, `.success`, `.error`, `.warning`, `.info`, `.message`, `.loading`, `.promise`, `.dismiss`, `.custom`) is available with full TypeScript inference. vue-sonner spells a few options the Vue way: `class` (sonner's `className`), `classes` (`classNames`) and `descriptionClass` (`descriptionClassName`), and `toast.custom` takes a component.

### Types

`Action`, `ExternalToast`, and `ToastT` are re-exported so you can type helpers without importing from `vue-sonner` directly.

## Theme sync

`<Toaster />` reads `data-theme` on `<html>` on mount and observes changes via `MutationObserver`. Toggling light and dark rethemes toasts that are already on screen, with no extra theme dependency.

## Differences from React

The Vue Toaster wraps [vue-sonner](https://vue-sonner.vercel.app/) 2.0.9, the Vue port of the sonner library the React Toaster uses. Plex styles, icons, defaults and theme sync are the same, and the wrapper aligns the markup it can reach. A few differences come from vue-sonner itself:

- With no toasts on screen, an empty `<ol data-sonner-toaster>` stays in the page; React renders no list.
- When a promise toast settles, its spinner is removed at once instead of fading out.
- When several toasts are created in the same tick, their stack offsets can come out in a different order until the next toast arrives. Toasts created one after another stack the same way.
- A plain `toast()` or `toast.message()` carries `data-type="default"`, which React leaves unset. Nothing visible changes.
- Each toast's `--z-index` counts down from 0 instead of from the number of toasts. The stacking order is the same.
- Action and cancel buttons print `data-button`, `data-action` and `data-cancel` as empty strings rather than `"true"`.
- A per-toast `closeButton` adds `data-close-button-position`, which vue-sonner's stylesheet uses to place it.
- Attributes passed to `<Toaster>` that are not props land on the `<ol>`; React drops them.
