<UsageBlock>{`import { Toaster, toast } from "@plexui/vue/components/Toast";`}</UsageBlock>

Render `<Toaster />` once near the root of your app, then call `toast(...)` from any handler. PlexUI renders toasts and manages their interaction while [vue-sonner](https://vue-sonner.vercel.app/) supplies the toast store. It retains vue-sonner’s toast API (`toast.promise`, `toast.loading`, `toast.dismiss`, `toast.custom`). The examples call `toast` from the template; in an app, import it in `<script setup>`.

PlexUI implements the compatible vue-sonner `Toaster` options (`expand`, `visible-toasts`, `hotkey`, `dir`, `swipe-directions`, etc.) in its renderer. `theme`, `rich-colors`, `toast-options`, `style` and `close-button` are left out of `ToasterProps`, because Plex sets them for its tokens, icons and theme sync. The `success-icon`, `error-icon`, `warning-icon`, `info-icon`, `loading-icon` and `close-icon` slots replace the default icons.

### toast

vue-sonner's `toast`, wrapped so a per-toast `descriptionClass` reaches the description as in React. The full surface (`toast()`, `.success`, `.error`, `.warning`, `.info`, `.message`, `.loading`, `.promise`, `.dismiss`, `.custom`) is available with full TypeScript inference. vue-sonner spells a few options the Vue way: `class` (sonner's `className`), `classes` (`classNames`) and `descriptionClass` (`descriptionClassName`), and `toast.custom` takes a component.

PlexUI renders and manages toast interaction in both frameworks while retaining [vue-sonner](https://vue-sonner.vercel.app/) as the Vue toast store. Timers, swipe cancellation, focus restoration and hidden-toast accessibility follow the same behavior. Vue-specific option names and custom components follow vue-sonner’s API.

### Types

`Action`, `ExternalToast`, and `ToastT` are re-exported so you can type helpers without importing from `vue-sonner` directly.

### Theme sync

`<Toaster />` reads `data-theme` on `<html>` on mount and observes changes via `MutationObserver`. Toggling light and dark rethemes toasts that are already on screen, with no extra theme dependency.

## Styling

Toast has no component tokens of its own. It reads the shared semantic color, typography and spacing tokens listed in [Design tokens](/docs/foundations/design-tokens), so it follows theme changes made there.
